Canonizing user intent

User intent is what you are trying to achieve, at every level: the product you have in mind, the feature that serves it, the behaviour that proves the feature works. It lives in your head, and a coding agent sees only the prompt in front of it.

HeadCanon writes that intent down as a canon, in your own words, and keeps the agent working from it, checking against it, and stopping to ask when the two disagree.

What goes wrong without it

AI coding agents lose track of what the human is trying to build, especially in large projects and over many iterations. Prompts alone leave the agent with a partial picture. Three failures follow. Pick one to see how it happens.

How it works

Your intent becomes a canon

A canon is a folder of plain files in your repository, versioned with the code, that records your intent towards your product. Canons are organized into increasing levels of detail, and an agent working on a feature only needs to care about its local canon.

A second agent keeps the canon whole

While you work, a secondary agent keeps track of the entire canon. It highlights contradictions, asks for disambiguation when two readings are possible, and asks for your approval before anything counts as your word. You and the agent maintain the canon together.

Intent history

Every commit names the intent it serves: a commit-msg hook asks for trailers that point at the requirement, journey or decision behind the change, and changes to the canon itself pass a review by a verifier agent before they land. The history of the code becomes the history of why.

Tests that hold your intent

A leaf of the canon is a statement that is either met or not, written before the code. That is what lets the system create real end-to-end tests of what you asked for, instead of tests written after the fact to pass.

Writ is the tool that will run these in CI/CD, as a gate on every commit, pull request or release, reporting which intentions are verified, which rest on assumptions and which are untested. It shares the canon format and is not started yet.

Every entry carries its certainty

Nothing in a canon pretends to be more settled than it is. Each node and journey step carries one of five states, and the agent can only move something to the human's own words with the human's click.

stated your words assumed the agent's guess open a known unknown contested you disagree resolved agreed, recorded

Try it on a project

There is no packaged release yet: the plugin runs from a checkout of the repository. You need Node 20 or newer and Claude Code. The build output is not committed, so build once after cloning and again after every git pull.

# 1. get the plugin and build it
git clone https://github.com/Althis/headcanon.git
cd headcanon
npm install
npm run build

# 2. start Claude Code inside the project you want to align,
#    pointing at the checkout you just built
cd /path/to/your-project
claude --plugin-dir /path/to/headcanon

The plugin loads for that session only. Then run /headcanon:adopt. It installs a commit-msg hook in your repository that asks every commit for the intent it serves, and the first session is a long one: adoption is what the current test runs exercise. The skills it adds:

/headcanon:adoptStart the canon from the project's existing artifacts and your words, then review the draft on the canvas.
/headcanon:attendKeep refining the tree in the background while you work in the page.
/headcanon:captureTurn what a conversation established into a change request you approve.
/headcanon:reviewWalk the assumed, open and contested items one at a time.
/headcanon:commitCompose a commit with the intent trailers and run it through the hook.

HeadCanon is built with itself: its own repository has carried a canon and the intent trailers since the first commit. The design brief that started it is in the repository.
