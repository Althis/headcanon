# Aim: the canon holds explanation, requirements are the reference, how-to guides trace to journeys

## Stated

> please record these as something we want to aim towards. The link between explanation and the canon, specs and reference, and how-to guides linking to journeys. We don't need to expand this now, in fact we have more pressing concerns for now.

Source: Claude Code session, 2026-10-11.

## Intent [assumed]

A direction for how a project's documentation and its canon fit together, to be worked out when documentation becomes the pressing concern. Of the four kinds of documentation Diataxis names, two are the canon's: explanation, since purpose, principles, non-goals and decision records are the why and live nowhere else; and the reference of what the product must do, since the requirement tree is that contract and the glossary its vocabulary. Code-level reference stays beside the code and is reached from a requirement through its file links. A how-to guide is the written form of a journey and traces to it; a tutorial traces to the onboarding journeys.

## Open

- 2026-10-11: whether an adopted project's existing explanation documents become decision records and principles, or are mostly current-state description to be dropped, is decided when a project folds its docs in.
